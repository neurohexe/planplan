# План-факт на мини-ПК

Код основного стенда «План Факт»: Django и PostgreSQL, общий веб-интерфейс,
тесты и сценарии установки, обновления и восстановления.
Проект находится в `junk/padolskiye/plan_fact_minipc`.
Поставка `taxi/int_real_estate/plan_fact` развивается отдельно.

## Версия и источник

На основном мини-ПК 5 ноября 2026 года установлена версия
`ee8fdfc20a5cc584a82f0a8da7ec8f37865b064c`.
Исходники перенесены из чистого Git-коммита мастерской
`c12b612918eecf5808b3019a9451ef0979bab86d`: он отличается от установленной версии
только записью об успешном обновлении в `MVP-STATUS.md`.

Все 278 отслеживаемых файлов мастерской перенесены без изменения содержимого.
`source-manifest.json` содержит их размеры, режимы доступа и SHA-256.
README, `.arcignore` и сам manifest подготовлены для этой копии в Аркадии.

В работающую установку входят `~/planfact` (сервер и сценарии обслуживания)
и `~/PlanFactMVP` (интерфейс и данные). Прежний снимок только из
`~/PlanFactMVP/app` не содержал Django и был неполным источником проекта.

## Состав

| Каталог | Назначение |
| --- | --- |
| `app/` | Общий интерфейс и его тесты |
| `backend_django/` | Основной сервер, миграции, бизнес-правила и тесты |
| `deploy/linux/django/` | Комплект установки, безопасное обновление, резервные копии и восстановление |
| `backend/` | Прежний сервер Node.js, его миграции и тесты совместимости |
| `deploy/linux/`, `deploy/laptop/`, `deploy/move/` | Обслуживание, учебные проверки и прежние сценарии переезда |
| `scripts/` | Сборка статических файлов и проверки |
| `MVP-STATUS.md` | Журнал реализации и проверок; задача 42 описывает установленное обновление |

В репозиторий входят только отслеживаемые исходники. Рабочие базы, дампы,
личные коды, `config.env`, окружения Python, зависимости Node и `.sandbox`
хранятся отдельно. `deploy/certs/YandexInternalRootCA.pem` — публичный корневой
сертификат, используемый сценариями корпоративного подключения.

## Разработка и проверки

Подробная инструкция основного сервера — в [backend_django/README.md](backend_django/README.md).
Нужны Node.js 22, Python 3.12 и PostgreSQL 14+; проверенная версия базы — 16.
Зависимости Node закреплены в `backend/package-lock.json`, Python — в
`backend_django/requirements.txt`.

Из корня проекта:

```sh
npm --prefix backend ci --ignore-scripts
npm run check
npm test
```

Сервер Django использует окружение `backend_django/.venv`; учебная PostgreSQL
поднимается `backend_django/tools/dev-postgres.sh`. Команды настройки и запуска
тестов приведены в README сервера. Ручные запуски — в `.sandbox/` на портах 18767+.

Перед установкой этой версии в мастерской прошли 328 Node-тестов (6 пропусков),
6 отдельных проверок PostgreSQL, 84 Django-теста и длинная сверка Node/Django
на 72 000 шагах. На учебной Linux-машине проверены обновление, восстановление
и автоматический возврат к прежнему коду и базе после намеренного сбоя.
Результаты установки и сохранности данных записаны в задаче 42 журнала.

При переносе в Аркадию повторно проверены SHA-256 всех 278 исходных файлов,
`npm run check`, `npm test` (334 теста: 328 успешных, 6 пропущенных), 14 тестов
Python и короткой сверки Node/Django. Синтаксис проверен для всех 53 файлов Python
и 63 сценариев shell. Полный набор Django и длинная сверка повторно не запускались.

## Установка и границы поставки

Действующий Django обновляется сценарием `update-django.sh` из нового комплекта.
Повторная установка и переключение с SQLite для обновления не подходят.
Сборщик `build-bundle.sh` пока использует Git: сборка проверенной поставки выполнялась
из коммита мастерской; самостоятельная сборка комплекта из Arc ещё не адаптирована.

Вход основного стенда — по личным кодам. Корпоративный вход WebAuth/IDM/TVM
не перенесён в Django. Расширенные правила закрытых месяцев остаются отдельным
решением владельца.

`AGENTS.md`, `CLAUDE.md` и материалы `tasks/` сохранены из мастерской для контекста.
Их Git-команды относятся к исходной мастерской; в этой копии управление кодом
выполняется через Arc. Изменение кода в Аркадии само по себе не обновляет стенд.
