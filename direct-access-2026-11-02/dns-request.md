Просим создать внутреннее DNS-имя веб-приложения «План-факт»:

```
plan-fact-office.yandex-team.ru. CNAME zomb-vodeyko-132.zombie.yandex.net.
```

Владелец приложения — ABC-сервис [int_real_estate](https://abc.yandex-team.ru/services/int_real_estate/) (ID 62226), контакт — padolskiye.

Приложение размещено на офисном мини-ПК под учётной записью zomb-vodeyko. Нужен понятный адрес для доступа участников ABC из офиса и корпоративного VPN. Планируемый веб-адрес — `https://plan-fact-office.yandex-team.ru/`, TCP 443. По сообщению владельца, ServiceDesk рекомендовал оформить доступ через Puncher от логинов или ABC-группы.

Проверено 02.11.2026:

- `plan-fact-office.yandex-team.ru` возвращает NXDOMAIN.
- `zomb-vodeyko-132.zombie.yandex.net` имеет AAAA `2a0e:fd87:8050:d01:4a21:bff:fe76:6dfe`; A-записи нет.
- ServiceDesk подтвердил исправление DNS основного имени в [HDRFS-4219055](https://st.yandex-team.ru/HDRFS-4219055).
- Приложение на мини-ПК слушает `127.0.0.1:18766`, `/api/ready` отвечает HTTP 200, `status=ready`. TLS-вход на TCP 443 ещё предстоит настроить; данная заявка относится к имени.

CNAME запрашиваем к существующему имени машины, без фиксации текущего IPv6 в новой записи. Доступ через Puncher от `@srv_svc_int_real_estate@` к основному имени мини-ПК на TCP 443 оформляется отдельно. В [FAQ Puncher](https://docs.yandex-team.ru/puncher/faq) есть ограничение на назначения-пользователей/зомбиков; создание DNS-псевдонима само по себе это ограничение не устраняет.

Просим согласовать и создать указанную запись для внутреннего использования. Если такая запись к устройству типа «зомбик» не поддерживается, просим сообщить допустимый вариант для этого адреса и устройства. Существующие имена и адрес `plan-fact.in.yandex-team.ru` не изменять.
